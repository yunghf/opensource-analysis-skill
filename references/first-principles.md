# 角度三：第一性原理分析（详细方法）

目标：回到不可再分的基本事实，推导哪些设计是必然的。这是让分析"有深度"的关键角度。

## 1. 方法论

第一性原理 = 连续追问"为什么必须这样"，直到遇到不可再分的基本事实，然后**从基本事实重新推导整个系统**，区分"必然设计"与"偶然设计"。

**错误做法**：罗列技术选型（"用了 SQLite 所以…"）。
**正确做法**：先定义系统面对的根本问题，再推导。

## 2. 根本问题（一句话）

模板：*"一个<有缺陷的智能体/快速演化的业务/不确定的外部世界>，要<可靠/一致/可审计地>完成<什么>"*

例（UOM 项目）："一个不可靠的智能体（LLM），要可靠地操作系统化的业务数据。"

## 3. 归纳基本事实（2~4 条）

从三个层面各取其一，确保覆盖面：
- **本体论层面**：系统的对象世界由什么构成（如：业务世界 = 可识别的事实 + 事实之间可追溯的联系）
- **认知论/能力层面**：系统的使用者/调用者有什么能力边界（如：LLM 擅长意图→声明，不擅长保证一致性）
- **工程论层面**：系统面对什么演化压力（如：业务结构必然演化，成熟机制应保持稳定）

每条基本事实必须：
- 不可再分（继续追问没有更基础的答案）
- 附一句"它推翻了什么表面答案"（例如：表模型假设"结构已知且稳定"——被"事实类别开放演化"推翻）

## 4. 从基本事实推导必然设计

对每个设计判断它服务于哪条基本事实，并给出代码证据。推导句式：

> 事实②说 X，因此"让调用者直接写库"不可接受 → 必须插入可验证中间层 → 所以 preview→confirm→apply 链条必然存在（证据：file:method）。

检验标准：**一个设计如果不服务于基本事实之一，就是装饰；如果服务于，就是必然。**

## 5. 诚实列出代价

第一性原理要求直面边界。常见代价维度：
- 约束强度的转移（从"不可能错"降级为"错了会被拦住"）
- 通用性换来的性能代价
- 开放词汇的语义治理成本

## 6. 常见推导链示例（可复用）

- 事实"事实类别开放演化" → 结构必须开放（type 字符串 + 半结构化 properties）→ schema 从"预先定义"变为"按需声明"
- 事实"调用者不可靠" → 写入必须经过 声明→编译→预览→确认→审计 → 每个环节都要可解释
- 事实"机制稳定/词汇演化" → 固定元模型 + 开放模型层 + 领域声明层 → 依赖方向单向
- "状态是历史的投影" → 保存历史流水、推导状态，而不是直接保存状态（审计器用金额推导状态）

## 7. 报告章节模板（与角度四合并时）

```
1. 第一性原理回顾：三个基本事实（卡片式，每条：本体/认知/工程 + 推翻的表面答案）
2. 代码巧思全景（按层：存储/工作区/DSL/领域/集成/Agent）
3. 巧思 → 基本事实映射表（闭环）
4. 综合结论（一句话还原系统的第一性原理）
```
