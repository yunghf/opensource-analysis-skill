# 产物形态规范（Output Formats）

> 分析做完了，**交付成什么形态由用户决定**。本文件定义三种形态的能力边界、选择矩阵、规格与校验方式，以及通过原生候选项收集偏好的标准问法。

## 1. 三形态能力边界（先看这张表再决定）

| 维度 | HTML | Markdown | SVG |
|------|------|----------|-----|
| **承载内容** | 长报告、多图、多表 | 长报告、代码块、表格 | **只承载图形**（图 + 少量标注） |
| **阅读体验** | ★★★ 侧栏 TOC、滚动高亮、可折叠卡片 | ★★ 取决于宿主渲染器 | ★★ 一屏一图，无滚动 |
| **可编辑 / 可 diff** | ★ 手改成本高 | ★★★ 纯文本，进 git 友好 | ★★ 文本 XML，但手改定位差 |
| **可被下游消费** | ★ 需浏览器 | ★★★ 可被其他 AI / 静态站点 / 文档系统直接吃 | ★★ 可插入 PPT / Word / 设计工具 |
| **缩放 / 打印** | ★★ | ★★ | ★★★ 矢量无损 |
| **单文件零依赖** | 是（本规格强制） | 是 | 是 |
| **适合谁** | 汇报、评审、归档、给不写代码的人看 | 沉淀进仓库文档、给 AI 继续加工、给人编辑 | 只要图：放进 PPT/文档/设计稿 |

**一句话决策**：
- 要**给人看、要好看、要能分享** → HTML
- 要**进仓库、要能被改被 diff** → Markdown
- 要**把图拿走用在别处** → SVG

**专业判断（不必问用户，直接在①段告知）**：SVG 无法承载长篇论证。若用户只选 SVG，交付的是"多视角图形卡片（每张一个分析视角）+ 一份简短 Markdown 索引"，**不会**把报告内容硬塞进 SVG 里的 `<text>`。

## 2. 选择矩阵（按场景给默认建议）

| 用户场景 | 推荐 | 理由 |
|---------|------|------|
| 技术尽调 / 竞品调研（要交给别人） | **HTML + Markdown** | HTML 给人看，MD 进知识库 |
| 二开前自己摸底 | **Markdown** | 要边看边记，可能要引到代码注释里 |
| 面试准备 | **HTML + SVG** | HTML 通读，SVG 导图用来背 |
| 只想知道"这项目长什么样" | **SVG（架构图 + 导图）+ Markdown 摘要** | 图最快建立认知 |
| 归档 / 沉淀进仓库 docs | **Markdown**（可选 HTML） | HTML 在仓库里会变死文件 |
| 全部都要 | **三者都出** | 成本可控（MD 是源，HTML/SVG 由它派生） |

**默认值（用户没选时）**：`Markdown + HTML` 成对产出（沿用主流程原规范），图形产物统一另出一份 SVG。

## 3. 各形态规格

### 3.1 HTML

沿用 `references/html-report-spec.md`，硬性要求：

- 单文件、**零外部依赖**、`file://` 双击可开（禁 CDN / 外部字体 / 外链图片）
- 复制 `assets/report-template.html` 作骨架，不要从零写 CSS/JS
- 必含：左侧 TOC + 滚动高亮（scrollspy）、代码框、卡片、表格、时间线/流程图、可折叠区块
- 页脚含报告名与互链
- 校验：`<!doctype html>` 开头 / `</html>` 结尾 / `<html>` 与 `</html>` 各 1 个 / `<script>` 与 `</script>` 各 1 个 / `node --check` 通过

### 3.2 Markdown

- 顶部必写：**分析对象 / 数据来源 / 分析日期 / 结论先行**（一段话）
- 标题层级 ≤ 4 级；表格优先；代码引用用 fenced block 并标注文件路径
- 图形用 Mermaid 代码块内嵌（`mindmap` / `flowchart` / `sequenceDiagram`），并**同时给一份纯文本缩进版**（宿主不渲染 Mermaid 时仍可读）
- 引用代码必须与仓库现状一致——**先读文件再引用**，不凭记忆
- 校验：`grep -c '^```'` 为偶数（代码块闭合）；无 `[TODO]` 残留；无绝对路径泄漏到正文

### 3.3 SVG

- 单文件 `.svg`，`<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 W H">`，`width/height` 可省
- **全部样式内联**（`fill` / `stroke` / `font-size` 直接写在元素上），**禁** `<style>` 里的外部类、禁 CDN、禁外部字体（用 `font-family="sans-serif"` 或系统中文字体栈）
- 文字用 `<text>` + `<tspan>`；中文字体栈：`font-family="-apple-system, 'Segoe UI', 'Microsoft YaHei', sans-serif"`
- 字号 ≥ 11px（缩到 50% 仍可读）；连线用 `<path>` 三次贝塞尔（水平出、水平入最稳）
- 配色跟随报告主题；深浅取决于用户 IDE 主题（浅色主题用浅底深字）
- **每个 SVG 自带图题**：顶部一行 `<text>` 写明"<项目名> · <视角名>"
- 校验：`xmllint --noout`（若有）或 Python `xml.etree.ElementTree.parse` 可解析；`grep -E 'https?://'` 除 `www.w3.org` 命名空间外无命中

**常用视角（一个视角一张 SVG）**：

| 视角 | 画什么 |
|------|--------|
| 定位卡 | 项目名 / 一句话定位 / 语言 / 许可证 / 活跃度 |
| 分层架构 | 层 → 模块 → 关键文件，标依赖方向 |
| 核心数据流 | 入口 → 校验 → 处理 → 持久化，标文件路径 |
| 思维导图 | 全景导图（见 `mindmap-spec.md`） |
| 质量热力 | 复杂度/规模 Top 文件，按档位配色 |
| 技术栈矩阵 | 七维度 × 选型 |

## 4. 交互：用原生候选项收集形态偏好（标准问法）

**这是 G1 前置门的一部分，与分析目标、深度档一起问，一次问完，不要分次打断。**

用宿主原生问答能力的选项机制（WorkBuddy 的 `AskUserQuestion`，最多 4 题、每题 2~4 选项）。形态题的标准设计：

| 字段 | 内容 |
|------|------|
| 题面 | `分析报告要什么形态？` |
| header | `产物形态`（≤12 字） |
| 选项 A（推荐，放第一） | `HTML + Markdown` — 描述：`HTML 好看可分享，Markdown 可编辑可进仓库；最通用的组合` |
| 选项 B | `只要 Markdown` — 描述：`纯文本、可 diff、方便进 git 和你自己的文档体系` |
| 选项 C | `只要 HTML` — 描述：`交互式单文件，适合直接汇报/评审；不产出 md` |
| 选项 D | `加出 SVG 图` — 描述：`在既有报告之外，额外产出架构图/思维导图等独立 SVG，可插 PPT` |

> 选项 D 是**叠加**而非替代：SVG 承载不了长篇论证，把它做成"第 4 个互斥选项"会让用户在"要报告"和"要图"之间被迫二选一。多选场景用 `multiSelect`，或把 D 描述为叠加项。

**回复语法**：用户可能只回 `A`、`A+图`、`都要`。`都要` → 三形态全出。未回答 → 取默认值 `Markdown + HTML`，并在交付时说明"用的是默认形态，可随时要求补出其他形态"。

## 5. 不落盘的即时展示（区别于上述三形态）

分析过程中，**不要等文件生成才让人看到东西**。用宿主的内联可视化能力（`show_widget`）在对话里直接流式渲染：

- Step 0 后：一张"仓库总览卡"（定位 / 语言构成 / 分层初判）
- Step 1 后：分层架构图
- Step 4 后：巧思映射图
- Step 7 前：思维导图骨架（先看图确认结构对不对，再落盘成文件）

规则：
- 内联展示**不替代**产物文件，是"进度可视化"与"结构预确认"
- 内联 SVG 必须遵守 §3.3 的零依赖与配色规则，`viewBox` 从 `0 0 680 ` 起
- 配色必须跟随当前 IDE 主题（浅色主题 = 浅底深字）

## 6. 形态与产物清单的对应

| 用户选 | 产出 |
|--------|------|
| HTML + Markdown（默认） | `analysis/*.md` + `analysis/*.html`（每份报告成对）+ 思维导图 md |
| 只要 Markdown | `analysis/*.md`（含 Mermaid 源码 + 纯文本树） |
| 只要 HTML | `analysis/*.html`（HTML 内自带完整内容，不依赖 md） |
| 加出 SVG | 上述任一 + `analysis/svg/<视角>.svg`（每视角一张） |
| 全部 | 上述全部 |

> 无论选哪种形态，**报告数量与内容深度不变**，变的只是载体。不许因为"用户只要图"就把分析做浅。

## 7. 交付时必说的三句话

1. **产物在哪**：列出实际生成的文件路径（HTML 说明如何打开）。
2. **形态是什么**：说明本次用的形态，以及"可随时要求补出其他形态"。
3. **哪些门未经确认**：若走了 `autopilot`（用户说"你定"），必须声明哪些判断是 Agent 自己做的。
