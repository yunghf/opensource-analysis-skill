# 角度二：git 演化分析（详细方法）

目标：从提交历史还原"架构是怎么演化来的"。以提交为证据，不臆测。

## 1. 全量历史与阶段划分

```bash
git log --all --format="%h %ad %s" --date=format:"%Y-%m-%d" | head -100   # 时间线
git log --all --format="%h %s" --name-only | head -200                    # 每提交文件清单
```

按时间把提交归入阶段，阶段类型：
- 范式切换（整个数据/建模方式被推翻重来——最高价值）
- 重命名级重构（拆包、改名、移动——看职责如何迁移）
- 增量功能（新增领域、新增能力）
- 文档沉淀（设计文档、规范）

## 2. 识别关键提交

优先级排序：
1. 删除大量旧文件 + 引入新范式的提交（范式切换）
2. 大比例 rename（git 会自动检测 similarity）——用 `git show --stat` 看 rename 箭头
3. 提交信息含 refactor/rebuild/separate/unify/redesign/reset
4. 对基础层/核心文件有实质改动的提交

## 3. 关键提交深挖（必做动作）

```bash
git show <commit> --stat                        # 文件级变化
git show <commit> -- <old-path> <new-path>     # 具体 diff（如 rename 前后）
git show <commit>~1:<old-path>                  # 旧版本文件内容
git show <commit>:<new-path>                    # 新版本文件内容
git ls-tree -r --name-only <commit> | head      # 某时刻全文件清单
```

对关键提交输出：
- **文件迁移对照表**（旧路径 → 新路径 → 职责变化）——rename 是最清晰的分层证据
- **语义移动方向**：领域函数下移到领域声明/文件？通用函数上移到基础层？（"上移 = 抽象化，下移 = 领域化"）
- **注册方式变化**：硬编码字典 → 字符串声明 + 动态加载（"从改代码到改声明"）
- **schema/命名变化**：本体 schema 版本、adapter 名、数据库名——命名变化反映概念边界移动

## 4. 领域反向驱动基础层的证据

这是"基础层如何被炼成"的关键信号：当第二个领域出现后，基础层文件被修改的提交。逐行 diff 看新能力（前置条件 DSL、上下文解析、可覆写钩子）如何被下沉进基础层，并检查是否开放了领域扩展点。

## 5. 演化规律总结

两张表：
- **维度对比表**（≥6 行）：领域实体表示 / 数据形态 / 操作定义 / 函数注册 / 本体归属 / 包结构 / 新增领域成本——"演化前 vs 演化后"
- **驱动力量**（2~4 条）：范式觉醒、工具/工作台驱动、领域需求反向驱动、文档沉淀后再实现

## 6. 报告结构模板

```
# <项目>基础层与领域模型演化分析报告
> 依据 git 历史（N 个提交，起止日期）/ 核心发现
1. 演化时间线总览（阶段化列表或可视化时间轴）
2. 阶段 A~N 详解（每阶段：时间/提交/关键变化/代码证据）
3. 决定性重构深挖（文件迁移对照表 + 三条分层本质）
4. 领域需求反向驱动基础层（diff 证据）
5. 演化规律总结（维度对比表 + 驱动力量）
```
